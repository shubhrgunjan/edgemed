## 1. The Unified Memory Conceptual Model

In EdgeMed, a "memory" is an integrated clinical knowledge record that spans vector, relational, temporal, and governance domains. Every memory conceptually contains the following fields:

```
┌────────────────────────────────────────────────────────────────────────┐
│                        CONCEPTUAL MEMORY RECORD                        │
├────────────────────────────────────────────────────────────────────────┤
│  1. id                  : Unique Identifier (UUIDv5)                  │
│  2. content             : Raw Clinical Observation / Note Text         │
│  3. embedding           : 384-dimensional dense vector representation  │
│  4. timestamp           : ISO-8601 UTC creation timestamp              │
│  5. source              : Originating modality (CLINICIAN, LAB, SENSOR)│
│  6. device_id           : Unique physical edge device identifier       │
│  7. category            : Clinical domain (OBSERVATION, DIAGNOSIS, etc)│
│  8. confidence          : Semantic and observational confidence [0..1] │
│  9. importance          : Clinical criticalness score [0..1]           │
│ 10. recurrence          : Occurrence frequency counter                 │
│ 11. freshness           : Temporal recency decay score [0..1]          │
│ 12. privacy_level       : PUBLIC | INTERNAL | SENSITIVE | HIGHLY_SENS  │
│ 13. provenance          : Cryptographic origin and transformation DAG  │
│ 14. entities            : Linked clinical entity node IDs              │
│ 15. relations           : Directed relationship edges to other memories │
│ 16. lifecycle_state     : LOCAL | SYNC_CANDIDATE | EXPIRED             │
│ 17. sync_state          : PENDING | SYNCING | COMMITTED | FAILED       │
│ 18. version             : Monotonic integer version counter            │
└────────────────────────────────────────────────────────────────────────┘
```

## 2. Field-by-Field Definition and Semantic Purpose

| Field Name | Data Type | Purpose and Architectural Role |
| :--- | :--- | :--- |
| **`id`** | `UUIDv5` String | Deterministic cryptographic identifier derived from device ID, timestamp, and content hash. Prevents ID collisions across distributed edge nodes. |
| **`content`** | `String` | The raw text of the synthetic clinical finding, nursing note, or lab observation. |
| **`embedding`** | `List[float]` (384) | Dense vector generated by FastEmbed (`bge-small-en-v1.5`) used by Qdrant Edge for nearest-neighbor semantic search. |
| **`timestamp`** | `String` (ISO-8601) | Precise UTC time of clinical capture. Drives the temporal progression engine and conflict resolution ordering. |
| **`source`** | `Enum` | Originating source: `CLINICIAN_NOTE`, `TRIAGE_VITALS`, `LAB_REPORT`, `IMAGING_REPORT`, or `SYSTEM_CONSOLIDATED`. |
| **`device_id`** | `String` | Hardware MAC/UUID of the capturing edge node. Crucial for tracing field provenance and device-specificity scoring. |
| **`category`** | `Enum` | Medical classification: `SYMPTOM`, `DIAGNOSIS`, `MEDICATION`, `ALLERGY`, `PROCEDURE`, or `VITAL_SIGN`. |
| **`confidence`** | `Float` [0.0 - 1.0] | Measurement or clinical certainty (e.g., automated lab analyzer = 0.98, tentative initial clinician impression = 0.65). |
| **`importance`** | `Float` [0.0 - 1.0] | Criticalness to patient survival and care (e.g., severe drug allergy = 1.0, routine temperature check = 0.25). High importance protects from eviction. |
| **`recurrence`** | `Integer` | Number of times this identical or semantically equivalent observation has been recorded. Incremented by the Consolidation Worker. |
| **`freshness`** | `Float` [0.0 - 1.0] | Calculated dynamic decay metric based on elapsed time and clinical category half-life (vitals decay quickly; chronic diagnoses decay slowly). |
| **`privacy_level`** | `Enum` | Security tier: `PUBLIC`, `INTERNAL`, `SENSITIVE`, or `HIGHLY_SENSITIVE`. Governs Privacy Firewall actions. |
| **`provenance`** | `Object` | Audit metadata: parent memory IDs, generating model name, source document hash, and transformation history. |
| **`entities`** | `List[String]` | Foreign keys linking this memory to formal ontology nodes in the SQLite Knowledge Graph (`Patient_01`, `Drug_Lisinopril`). |
| **`relations`** | `List[Object]` | Explicit typed directed edges (`CONTRADICTS`, `SUPERSEDES`, `DERIVED_FROM`, `TREATED_WITH`). |
| **`lifecycle_state`**| `Enum` | Active memory status assigned by Memory Governor: `LOCAL` (retained on edge), `SYNC_CANDIDATE` (ready for server), or `EXPIRED` (eligible for purge). |
| **`sync_state`** | `Enum` | Outbound synchronization queue status: `PENDING`, `SYNCING`, `COMMITTED`, or `FAILED`. |
| **`version`** | `Integer` | Monotonically increasing revision number used by conflict resolution algorithms to detect stale updates. |
